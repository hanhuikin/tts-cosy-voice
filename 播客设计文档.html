🎙 播客工坊 UI 与交互设计方案

CosyVoice FastAPI 服务 · 播客功能设计文档 v1.0  |  参考开源项目：Podcastfy（开源 NotebookLM 替代）的内容源→对话稿→TTS 管线

一、功能概述

在现有控制台中新增「播客工坊」视图，把当前的单人 TTS 合成扩展为多角色对话式播客生成：

  • 三种内容源：① 上传文件（txt / md / pdf / docx）；② 直接粘贴文本；③ 提供网页 URL，由大模型抓取并总结归纳
  • 大模型配置能力：兼容 OpenAI 协议（base_url / api_key / model 可配，支持本地模型如 Ollama、DeepSeek、Qwen 等），可测试连通性
  • 对话稿生成与编辑：LLM 将内容改写为「主播 + 嘉宾」多轮对话稿，生成后可人工逐句编辑、指派音色
  • 双输出模式：非流式（整段合成 → 成品 WAV 下载）与流式（逐句合成实时播放 / 推流）
  • 推流能力：流式输出支持 RTMP / SRT / RTSP / HLS 四种主流协议，界面显示可复制的推流地址与拉流预览地址

三、交互设计 — 内容源（三种方式）

3.1 粘贴文本

  • 默认选中项；字符上限 20,000，超出禁止生成并提示「内容过长，请分段」
  • 点击「🤖 生成对话稿」→ 按钮进入 loading → 对话稿区域流式渲染 LLM 输出（打字机效果），完成后进入可编辑状态

3.2 上传文件

  • 支持 .txt .md .pdf .docx（前端预检扩展名与大小 ≤20MB），拖拽上传
  • 服务端解析出纯文本后回显「文本预览（前 500 字）」，用户确认无误再生成
  • PDF/DOCX 解析失败时给出明确原因（加密 / 扫描件无文本层），引导改用粘贴

3.3 网页链接（URL 总结）

  • 输入 URL → 点击「抓取并总结」→ 服务端抓取网页正文 → LLM 归纳要点 → 直接生成对话稿
  • 抓取过程显示三态进度：抓取网页中… → 正文提取完成 (8,214 字) → LLM 改写中…
  • 失败处理：404/超时提示检查地址；反爬拦截（403）提示「该网站禁止抓取，可复制正文用粘贴文本」

五、交互设计 — 对话稿编辑器

  • 结构：每轮对话 = {角色, 音色, 语速, 文本}；角色用彩色头像区分（主播蓝 / 嘉宾紫，支持第三人）
  • 逐句编辑：点击任意气泡 → 文本变为输入框（Enter 保存 / Esc 取消）；删除某句后自动顺延
  • 音色快换：气泡上的音色名是下拉框，直接切换（联动右侧输出设置的角色默认音色）
  • 重新生成：保留内容源，重新调用 LLM（覆盖前确认）；「↻ 重写本句」可只重生成单句
  • 预估时长：按字数实时估算（约 4.3 字/秒 × 各角色语速），随编辑即时更新
  • 轮次控制：LLM 配置中的轮数偏好 + 生成后可手动增删，超过 60 轮提示拆分为多期

六、UI 设计 — 输出模式与推流面板

6.1 非流式（默认）

  • 整段队列合成（逐句依次调用现有 /api/tts，拼接为单文件）→ 播放器试听 → 下载 WAV / 存入播客列表
  • 进度条按「已合成句数 / 总句数」推进，单句失败不中断整体（跳过并标记，完成后可单独重试该句）

6.2 流式 + 推流

流式模式 = 逐句流式合成（复用现有 stream 管线）→ 音频流一边进播放器、一边按所选协议经 ffmpeg 推往目标地址。推流面板交互：

6.3 推流协议对比（面板中选择协议时展示对应地址格式提示）

协议地址格式典型场景延迟备注
RTMPrtmp://host:1935/app/streamKey推给 SRS / nginx-rtmp / 直播平台（B 站、抖音、视频号）1~3s最通用，首选默认
SRTsrt://host:9000?streamid=xxx广域网低延迟传输、专业导播0.5~1s抗丢包，需对端支持
RTSPrtsp://host:8554/podcast局域网监控类播放器（VLC）<1s适合内网调试
HLS推流无需地址；生成 http://host:8001/live/podcast.m3u8网页/手机 H5 直接播放6~15s服务端 ffmpeg 切片，本服务直接托管播放列表

实现要点：服务端以 ffmpeg 子进程为推流出口（ffmpeg -i pipe:0 -c:a aac -f flv rtmp://…），HLS 模式由 ffmpeg 写 m3u8/ts 分片到 server/data/live/ 并经 FastAPI 静态托管；进程生命周期与面板「开始/停止」按钮绑定，异常退出自动标记并提示 ffmpeg stderr 摘要。

八、后端接口草案（供实施参考）

方法路径说明
GET/PUT/api/llm/config读取 / 保存大模型配置（key 脱敏返回）
POST/api/llm/test连通性测试（返回延迟与模型名）
POST/api/podcast/source/extract上传文件 / URL → 提取纯文本（URL 走抓取）
POST/api/podcast/script文本 → LLM 生成对话稿（SSE 流式返回）
POST/api/podcast/episodes保存剧集（对话稿 JSON + 音色分配）
POST/api/podcast/episodes/{id}/synthesize合成：mode=final|stream；stream 时返回事件流（进度 + 首包）
POST/api/podcast/episodes/{id}/push开始推流 {protocol, url, audio_params}；DELETE 同路径停止
GET/live/{name}.m3u8HLS 播放列表（静态托管）
对话稿 JSON 结构：{role, voice_id, speed, text}[]；LLM 输出以 JSON Lines 约束（system prompt 要求逐行输出 JSON，逐行解析容错）。

九、依赖与风险

  • ffmpeg：推流必需依赖，Windows 下随包分发静态版或 winget 安装；启动时自检并在推流面板提示缺失
  • LLM Key 安全：仅本机存储；若服务暴露公网需增加访问控制（当前定位为本地工具）
  • 网页抓取：依赖目标站可访问性与反爬策略，明确失败提示与「复制正文」兜底路径
  • 流式拼接：逐句流式合成的句间由播放器按序调度（复用现有 2.5s 预缓冲机制），句间停顿由标点自然承担
  • 分期建议：一期做「粘贴文本 + LLM 对话稿 + 编辑 + 非流式成品」；二期加「文件/URL + 推流」；三期加多角色(3+人)与背景音
