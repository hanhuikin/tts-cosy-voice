UI / UX Design Proposal

Voice Studio 界面重构方案

面向多模型语音合成控制台的一次完整重设计：把技术参数藏到背后，让用户只做三件事——输入文字、选一个声音、听结果。方案基于现有 5 个视图与 7 个模型能力实测，可直接映射到当前 API。

01现状诊断与目标

先说清楚旧界面哪里卡住了人，再定义新界面要解决什么。

现状问题

  • 技术概念前置：用户必须先理解 sft / zero_shot / cross_lingual / instruct 才能开始合成。
  • 能力随模型漂移：7 个模型各自支持不同模式，4 个 Tab 需要动态增减，用户难以建立稳定心智模型。
  • 长表单堆叠：文本、模式、音色、模型、语速、流式、语言、指令全部平铺，首屏噪声高。
  • 结果与操作分离：生成完要去下方结果卡或右侧队列里找音频。
  • 诊断信息常驻：GPU、显存、队列、采样率、端口占着侧栏底部，属于排障信息而非日常信息。
  • 主题按钮位置随视图浮动，不符合「设置类控件位置固定」的预期。

设计目标

  • 把首屏决策从 4 步降到 2 步：输入文字 + 选声音。
  • 用「用谁的声音」统一表达 7 个模型的能力差异，模式由系统推导。
  • 结果常驻右侧，生成即可播放、下载、复用参数。
  • 高级参数默认收起，需要时才展开，不牺牲专业用户控制力。
  • 全局状态收敛到顶部模型切换器，异常时才打断用户。
  • 一致的明暗主题、键盘操作与响应式布局，桌面到手机都能用。
输入文本→选择声音→生成→立即播放模式 / 语种 / 语速由系统推导或折叠收纳

05核心界面决策

六个最关键的交互决定，以及它们如何消解多模型带来的复杂性。

① 用「选声音」替代「选模式」

三种声音来源构成稳定的心智模型：预置音色（模型自带）、我的音色（上传的参考音频）、声音设计（文字描述凭空生成）。用户选的是结果，不是算法；后端 mode 由选择推导。

② 能力差异由界面吸收

切换模型时，只显示该模型支持的声音分组与高级项；不支持的整行隐藏而不是置灰。若当前选择失效，自动切到第一个可用方式并给出一句解释。

③ 必填项永不折叠

Qwen3-TTS Base 的参考文本、VoiceDesign 的声音描述都是必填，直接出现在声音选择区下方；只有语速、语种、风格指令、流式这些可选参数才进「高级设置」。

④ 主 CTA 吸底且会说话

操作条固定在主任务区底部，左侧实时显示预计时长与当前参数；不满足条件时显示具体原因，而不是一个无声的灰色按钮。

⑤ 结果不离开视线

右侧输出面板常驻：空状态给引导、生成中给进度、完成后给波形播放器与下载/复用/保存。最近 4 条作品可直接回放。

⑥ 全局状态在顶栏

模型切换器带状态点，一次点击看到全部 7 个模型及其能力说明；GPU、显存、队列、端口等诊断信息收进系统状态页，异常时才用轻量通知提示。

05B播客工坊：保留全部功能，只重组结构

这一页的原实现功能密度最高。评审反馈「与原来差别较大」后，本版逐项对齐原能力：不删任何功能，只调整放在哪一栏、什么时候出现、状态怎么反馈。

约束：原有能力 1:1 保留，请求字段与后端接口完全不变；改动只发生在信息组织层。特别地，任务队列与播客列表是两个独立区块，任务详情单独成页，三者不得合并。

结构上的四处改动

① 加一条流程状态条

内容源 → 阵容 → 对话稿 → 成品，已完成 / 当前 / 待办一眼可见，同时显示轮数与预计时长，解决原界面「①②③④ 编号分散在不同列」的问题。

② 成品区从第三栏拆出

原实现把阵容、成品、流式、推流全塞进第三列，滚动到一半就找不到主操作。现在第三栏只放阵容，成品与发布做成全宽底部区并用 Tab 分层。

③ 任务队列与播客列表严格分开

两个独立分组、各自标题 / 计数 / 刷新 / 空状态：队列只跟踪已提交的任务并点进详情，列表收纳全部剧集并点进编辑器。合并成一个列表会同时破坏这两条操作路径。

④ 任务详情单独成页

点队列项打开完整详情面板：合成进度、推流协议与地址、停止推流、失败原因、试听下载、来源、阵容、创建时间、载入编辑器、删除剧集，不压缩成列表行里的一句提示。

补充验收项

  • 三种内容源各自可走通「直接朗读 / LLM 改写」两条成稿路径。
  • 对话稿编辑、换说话人、删除、插入、重新生成后，提交字段与原实现一致。
  • 「至少保留一位嘉宾」约束、语速与预计时长联动仍然生效。
  • 成品 / 流式 / 推流三个 Tab 状态互不串扰，推流关闭时不展示协议与地址。
  • 任务队列与播客列表是两个独立分组：各自有计数、刷新与空状态；draft 存稿只出现在播客列表。
  • 点击队列项打开任务详情面板，详情里 9 类信息（进度 / 协议 / 地址 / 耗时 / 错误 / 来源 / 轮数 / 语速 / 阵容 / 时间）与操作（停止推流 / 试听 / 下载 / 载入 / 删除）齐全。
  • 详情里停止推流或删除剧集后，队列与列表两处状态同步更新；剧集删除需要两步确认。
  • 进行中任务在切页后仍显示正确状态，刷新后能自动接管。

07状态与反馈

渐进披露

首屏只出现文本、声音、生成三个要素。高级设置默认折叠，展开后仍是 4 行以内；专业用户的控制力没有减少，只是不再挡路。

即时可预期

字数统计、预计时长、当前模型与语速实时显示在操作条，生成前就知道会得到什么。

不打断

成功与非致命信息用右下角轻提示（2.8 秒自动消失）；只有需要用户决策的错误才用内联卡片。

危险操作：删除音色、删除作品、未保存就切换模型等动作需二次确认，并在提示中提供撤销入口；纯 destroy 操作不使用不可逆交互。

09无障碍与响应式

无障碍

  • 所有交互控件有可见焦点环（2px 主色 + 2px 偏移），键盘可完整走通主流程。
  • 图标按钮带 aria-label；开关用 role="switch" + aria-checked；模型菜单用 listbox 语义。
  • 文本对比度 ≥ 4.5:1；状态同时用文字、图标与颜色三重编码。
  • 遵循 prefers-reduced-motion，关闭波形与过渡动画。
  • 主题记忆写入 localStorage，首帧前应用避免闪烁。
  • 快捷键：Ctrl/⌘+Enter 生成、空格播放/暂停、Esc 关闭菜单。

响应式三档

≥ 1180px三栏：导航 228 / 主区自适应 / 输出 336
720–1180px输出面板下移到主区底部，声音卡片 2 列
< 720px左导航变底部 Tab Bar，顶栏精简，卡片单列，操作条换行
< 460px全部单列，统计 2×2，通知全宽

原型已实现以上断点，可直接拖动窗口验证。

10落地路径与验收

这是设计方案与可交互原型，尚未改动线上 server/static/。建议按下面三步接入现有 Vue 应用。

① 先换设计系统

把本方案的语义 token 写进 style.css 的 :root[data-theme]，替换现有硬编码色值；组件类名沿用，视觉即可整体升级且不改逻辑。

② 再换创作台结构

把 4 个 mode Tab 换成三种声音分组；在 app.js 增加 group → mode/spk_id/voice_id/instruct_text 的推导函数，其余请求字段保持不变。

③ 最后调整 IA 与播客

结果区移到右侧常驻面板，侧栏底部诊断信息迁到系统状态页，主题按钮固定到顶栏；播客按 05B 的对照表逐项搬迁（加流程条、拆出全宽成品区、任务队列 / 播客列表两个独立分组、补任务详情面板），接口字段保持不变。

验收清单

  • 7 个模型逐一切换，声音分组与高级设置项与第 08 节表格完全一致。
  • 从「预置音色」切到只支持克隆的模型，界面自动纠正选择并给出原因说明。
  • 所有禁用态都显示具体原因，用户无需猜测。
  • 每种声音方式各完成一次真实合成，右侧能播放、下载、复用参数。
  • 明暗主题下文本对比度均 ≥ 4.5:1，键盘可完成「输入 → 选声音 → 生成 → 播放」全流程。
  • 720px / 460px 两个断点无横向滚动，主 CTA 仍可见可点。
  • 启用「减少动态效果」后波形与过渡动画停止。
  • 原有 41 例接口测试保持通过（UI 改造不应触碰请求契约）。
